# 第三批：有状态搜索调度器方案

> 本文保留该批次的设计和当时的源码位置。当前模块职责与路径见[架构说明](../architecture.md)。

`perf/reduction-strategy` 分支、`e8203a3`，第二批实现已由 `09de684` 合入。
2026-11-03 的设计、实现和对照均以完整第二批为基线；运行结果与退化样本见

## 目标与范围

把“下一次尝试哪个候选”从 engine 的嵌套循环中抽出来。在接受编辑后延续有效的
阶段、尺度和搜索位置，减少重复准备与检查，同时保留旧策略作为可选择的对照。

第三批包含运行内状态、稳定节点身份、自适应节点分区、反馈统计、版本失效和
固定点覆盖记账。模块识别、图结构区域划分、独立的快速/完整运行模式属于第四批；
跨运行恢复 scheduler、并行评估和共享权重存储不在本批实现范围。

首版采用确定性规则，`stateful` 显式启用，默认保留 `legacy`。
默认值切换需另行依据结果质量和性能验收，不能由架构调整本身推出。

## 第二批实测对方案的约束

第二批已经解决大量资源逐项删除和重复准备问题：512 initializer 的实际判定从
515 次降至 4 次；固定基准的重复候选中，shape 推导从 381 次降至 1 次。
这两类收益不能再次归因于 scheduler。

规模 32、固定候选检查预算 100 的第二批记录如下。实际判定均包含强制首尾检查：

| 场景 | 生成候选 | 接受候选 | 实际判定 |
| --- | ---: | ---: | ---: |
| chain | 15 | 6 | 13 |
| branches | 19 | 6 | 15 |
| outputs | 6 | 3 | 7 |
| missing-shape | 15 | 6 | 13 |

数据来自 `output/performance/batch2-five-after/20261103-114415/baseline.json`。
其中 branches 的 `remove_unused` 生成 6 个候选，只产生 1 次实际判定；其余内容已命中缓存。
因此“少访问一个阶段”不等于“少调用一次后端”。本批必须同时统计候选准备次数、缓存前的
重复尝试和实际判定数，不能只用判定数估算所有收益。

现有小规模单触发条件已经能较快缩到固定点。新增的保留方向、状态维护和最终覆盖也有成本，
不能预设它们在这些样本上更快。主要实验应增加更大规模、触发位置变化、跨区域和非单调条件，
观察是否减少旧区域重复探索，以及同等预算下能否得到更低的完整成本。

## 第二批基线提供的约束

| 位置 | 调整前行为 | 设计影响 |
| --- | --- | --- |
| `engine.py` 的 `_run()` | 首个接受候选结束内层循环，随后从首个 pass 重新开始 | 这里替换为 scheduler 驱动；接受门槛、预算、checkpoint 和复检仍由 engine 负责 |
| `passes/base.py` | pass 只有 `name` 和 `generate(model)` | 保留该协议，兼容第三方 pass；新调度能力通过可选接口接入 |
| `passes/delete_nodes.py` | 删除块大小从 `N//2` 逐次减半到 1 | 可用于原策略和最终覆盖扫描；现状不是全体连续区间穷举 |
| `edits.py` | `DeleteNodes` 持有相对于候选基准的索引 | scheduler 保存 ID，出队时才转换为当前索引；不改变编辑文件格式 |
| `model.py` 的 `_delete_nodes()` | 删除后调用 `graph.sort()` | 存活节点也可能重排，不能只对旧索引做减法修正 |
| `model.py` 的 `apply_candidate()` | 复合编辑逐项作用于前一项编辑结果 | 身份映射也必须逐项更新，不能把所有索引解释成原模型索引 |
| `report.py` / engine | 完整无接受轮次且无 inconclusive 才声明 pass 固定点 | 调度队列耗尽不等于最终基准上的完整覆盖 |
| `tests/test_performance.py` | 固定检查预算下，采集开关前后决策轨迹相同 | 默认调度不以墙钟耗时或可选采集数据排序 |
| `preparation.py` / evaluator | 编辑缓存绑定基准摘要；内容缓存按精确内容复用；`--no-cache` 关闭三类缓存 | scheduler 不另建判定缓存，也不能把旧区域失败当作内容命中 |
| `_record_candidate()` / `_record_evaluation()` | 候选日志保留各拒绝分支，判定计数只统计实际调用 | 反馈必须从实际分支产生，不能依赖开启性能采集或反推累计计数 |

当前顺序为 `drop_outputs → remove_unused → delete_nodes`。所有清理都需要故障判定，
死节点仍可能携带目标故障。成本继续使用现有字典序，节点下降时允许字节增加。

## 模块与反馈接口

新增 `scheduler.py`，两种调度器共享 engine 的候选执行路径：

- `LegacyScheduler` 精确复现现有 pass 顺序、候选顺序和接受后重启行为。
- `StatefulScheduler` 保存运行内状态、生成逻辑任务、接收反馈并决定后续任务。

调度边界如下：

```python
next_attempt(current_model) -> ScheduledAttempt | None
observe(attempt, feedback, accepted_model=None) -> None
coverage() -> CoverageSummary
```

`ScheduledAttempt` 包含当前基准上的 `Candidate`、所属 pass、模型版本、逻辑区域、
方向、尺度和来源。scheduler 不执行编辑、校验或判定，也不写 checkpoint。
engine 继续分配全局候选序号并核验 `base_digest`，同一时间只存在一个在途候选。

第二批的 `_try_candidate()` 只返回“模型或 None”，无法区分失败原因。
本批返回 `AttemptResult(feedback, accepted_model)`；`CandidateFeedback` 包含：

- `edit_failed / not_cheaper / invalid / not_interesting / inconclusive / accepted`。
- 原成本、新成本（尚不可得时为空）、目标身份不匹配、缓存来源（无、编辑、内容）
  和实际检查调用数（0 或 1）。
- 可选的 `preparation_seconds`、`evaluation_seconds`。前者计入候选执行中判定路径之外的
  准备与记录，后者包含判定、目标匹配及判定证据记录，排除模型落盘。精确后端执行时间
  另见性能采集的 `external_check`。计时仅在 `--performance` 开启时记录；关闭时为空。

反馈在包括编辑缓存命中在内的每个返回分支直接构造，不能从 `report.inconclusive`
或性能计数器的差值推断。内部 `accepted` 反馈仍对应现有候选日志的 `interesting`，
不改变候选 JSON 的编辑格式、状态含义和重放方式。

`next_attempt()` 返回空值表示当前基准的覆盖流程已结束，不能仅表示启发式任务暂时为空。
`CoverageSummary` 至少包含基准摘要、版本、覆盖范围、完成标志和最终扫描的不确定候选数。
engine 检查该摘要是否属于当前模型，并在最终产物独立复检通过后决定最小性状态。

预算终止沿用异常/停止路径，不当作候选失败。故障判定进程错误仍向外传播，
不能通过自动切回 legacy 隐藏错误。报告和候选证据继续由原来的统一路径产生。

`--scheduler legacy|stateful` 映射到 `EngineConfig`，初期默认 `legacy`。
每次 `run()` 创建新 scheduler，复用 engine 实例不能带入上一运行的状态。
仅通过显式可选能力启用节点专用状态，不能按 pass 名称或是否偶然生成了 `DeleteNodes`
识别内置节点搜索。只有实现该能力的节点 pass 才增加保留候选；自定义同名 pass
仍按自身 `generate(model)` 执行。配置需要节点状态但适配器不支持时，在首次后端调用前
明确报错；只配置通用 pass 的 stateful 调度无需强迫适配器提供节点协议。
回退通过显式选用 `legacy` 完成。

## 稳定节点身份

ONNX 适配器维护主图节点的旁路身份：

1. 原模型按初始主图顺序分配整数 ID；ID 仅在当前模型谱系内有效。
2. `copy()` 对克隆前后的对应主图节点传递 ID。不能沿用 Python 对象地址；
   克隆后建立新节点对象与旧 ID 的对应关系，并验证数量和顺序对应的假设。
3. 删除及排序后，根据仍存活的节点对象重建有序 `node_ids` 与 `id_to_index`。
   输入、initializer 和输出删除不改变存活主图节点 ID。
4. 身份不写入 ONNX 名称、属性、metadata 或序列化快照，不影响摘要和成本。
   重新加载产物会建立新的身份空间，不承诺跨运行身份连续性。
5. 无名、同名、相同算子或相同结构节点仍各有独立 ID；属性子图内部暂不分配搜索 ID。

当前依赖的 IR `Model.clone()` 会克隆图、节点和值，不能以克隆前对象地址识别新节点；
`Graph.sort()` 会对主图及子图重新排序。适配器可在持有当前节点对象时用旁路映射找 ID，
但对象到 ID 的映射随副本重新建立，删除后清除已删除对象，不能保留整条历史图谱。
克隆的顺序对应关系需由当前依赖的实现及回归用例验证，不通过导出模型或修改节点名称建立。

通过可选的 `NodeSearchModel` 协议暴露只读 ID 序列和索引映射；节点 pass 通过
`NodeSearchPass.node_regions()` 显式启用连续分区搜索。不强迫现有 `ModelAdapter`
或通用自定义 pass 实现这些能力。

scheduler 保存的是 `NodeRegion(ids)`，而不是可直接执行的旧 `Candidate`。
版本变化后先与当前存活 ID 求交，再按当前顺序规范化。出队时绑定当前摘要并生成
新的 `DeleteNodes(indices)`；消失的区域丢弃，空编辑不提交。
保留方向的补集也在出队时针对当前全部节点重新计算。

## 自适应分区和阶段延续

第一版以当前主图拓扑顺序的连续分区为基础，不加入模块识别。
设节点数为 `N`、目标块大小为 `s`，从 `s=max(1, N//2)` 开始；
每个区域按确定顺序产生两种逻辑任务：

- 删除区域：`DeleteNodes(region_indices)`。
- 仅保留区域：`DeleteNodes(all_current_indices - region_indices)`。

两者都沿用现有边界提升语义。仅保留区域并不意味着保留其依赖闭包，也不隐式删除
输出或资源；“仅保留”只描述主图节点集合。输出数量规则及模型校验仍然生效。
空补集跳过；同一基准上相同实际编辑可去重，例如二分时互为等价的删除/保留候选。
删除/保留双向任务与标准 ddmin 的子集、补集测试同源，粒度调整规则可对照
[ddmin 原论文](https://www.st.cs.uni-saarland.de/publications/files/zeller-tse-2002.pdf)。
`N=0` 无节点任务，`N=1` 仍尝试删除最后一个节点，不能要求至少留下一个节点。

一次接受后保留成功的方向、目标块大小和下一存活区域锚点，把块大小限制到新节点数。
更新后的分区及实际节点数是新版本任务；旧分区只提供位置和尺度提示。
分区始终按当前顺序从索引 0 每隔 `s` 个节点建立；锚点只决定先访问哪一块，
不改变分区边界。锚点取旧版下一块的首个 ID；消失时沿旧有序 ID 序列向后寻找
首个存活节点并允许环回，然后按其当前索引定位新块。不能用 ID 数值比较代替拓扑顺序。
同一尺度的一轮删除/保留任务无接受后，令 `s=max(1, s//2)`；尺度 1 也完成后才结束
该阶段。成功后不会立即把尺度重置成新模型的一半。

阶段采用有上限的轮转，每阶段最多连续处理 8 个候选尝试再让出，
成功接受也计入该额度。编辑失败、校验失败等未调用后端的尝试也计入，
避免某个阶段独占运行；模型版本更新不重置该阶段已用额度，否则连续接受仍会饿死其他阶段。
额度是待基准检验的内部常量，保留 1、4 两种对照值用于退化分析，不增加公开调参开关。
接受后优先延续当前阶段，其他阶段标记待重访，到轮转时重新生成当前基准候选。
这保留现有输出清理、无用资源清理和节点搜索的职责，且不会每次接受就抢回首个 pass。

对于仅提供 `generate(model)` 的通用 pass：只在版本不变时持有生成器；
版本一变必须丢弃并基于新模型重建。不能跨版本恢复旧生成器或机械跳过旧序号。
这类 pass 的首版优化限于阶段轮转，真正跨版本的内部细分状态需要可选专用接口。
第三批先为节点 pass 提供该能力；第二批清理算法仍由其 pass 自己负责。

首版状态转换固定为：初始化 → 阶段轮转与节点自适应搜索 → 当前基准覆盖 → 完成。
在任一搜索或覆盖步骤接受编辑，都增加版本、使旧覆盖失效并返回阶段轮转；
预算停止由 engine 中断当前流程并保留未完成状态，不把未完成扫描标成固定点。

## 版本、重访与固定点保证

维护单调递增的 `model_version`，只在接受编辑后增加。另保留内容摘要用于精确基准绑定。

- 当前版本的尝试记录可以避免重复调度；模型变化立即使覆盖证据失效。
- 旧版失败、无效和无法判定只能影响优先级，不能证明新版区域可跳过。
  即使区域内节点没有变化，其他区域的删除也可能改变全局故障条件。
- 每次接受后将所有阶段标为需要当前版本覆盖，受影响区域只获得更高重访优先级。
  第一版不以依赖局部性推断“其他区域无需重试”。
- `inconclusive` 只计入当前扫描的不确定性，不成为永久拒绝或负面缓存；
  同一轮不会无限重试它，后续版本可以再次尝试。
- 精确内容缓存仍可复用同一实际候选内容的确定性判定；这与复用旧区域失败不同。
  调度记录不替代第二批编辑缓存，也不改变 `--no-cache` 的判定缓存含义。

启发式队列耗尽后，必须对最终基准完成一轮确定性覆盖，才能报告固定点：

1. 遍历全部配置 pass 的当前候选，保持其原有候选定义。
2. 补充当前拓扑各标准尺度（`N//2` 逐次减半到 1，`N=1` 时为 1）的保留区域候选；
   删除区域已由默认节点 pass 覆盖。仅启用了显式节点搜索能力时才补充。
3. 任一接受使本轮覆盖失效，更新模型后返回调度；不能继续把旧覆盖当作新模型的证据。
4. 无接受且完成覆盖时才设 `stop_reason=fixed_point`；最终轮次有无法判定结果则
   `minimality.status=unproven`。预算中止也为 `unproven`，最终产物仍独立复检。

这是维护现有固定点语义所必需的扫描，不引入第四批的独立收尾模式。
报告应明确 scope 为“配置 pass 候选 + 已启用的标准分区保留候选”，记录被验证的摘要、
版本和覆盖是否完成。自适应过程中出现过的其他尺度不是最终保证范围，不能泛称
“全部区域固定点”，也不能声明全局最小。
`legacy` 保持既有 `minimality` 字段及作用域，新覆盖证据放入 `scheduler` 报告；
扩展后的候选作用域仅用于实际启用了保留方向的 stateful 策略。

最终覆盖保留配置 pass 的候选顺序与独立扫描游标，不能因启发式阶段“访问过相似区域”跳过。
首版允许这次扫描产生重复准备，确定结果通过第二批现有缓存复用；`--no-cache` 时按扫描
实际执行，仍须保持预算上限。覆盖阶段的调用、缓存命中和耗时单列，以便判断保证成本。
启发式阶段的同版本去重不得吞掉覆盖阶段的 `inconclusive`，也不能覆盖本轮的不确定性记录。
不因某一次不确定就永久阻止后续版本证明固定点；判断只依据最终基准的完成扫描。

只保留当前版本的有界去重记录和区域游标；历史统计按阶段/方向/尺度桶聚合，
不保存每个历史候选的整份节点集合或模型。去重表容量受限，淘汰只影响效率；
扫描进度由游标保证，不能依赖无限增长的集合来保证结束。

## 统计与排序

运行内记录阶段及尺度的尝试数、实际判定数、接受率、拒绝类型、准备/判定路径耗时、
接受成本变化、版本数、跨版本阶段重访数和续用尺度次数。区域锚点、方向与精确尺度另记入
`scheduler.jsonl`，不保留逐个历史区域的完整 ID 集合。缓存命中单列，避免把命中速度当作后端速度。
收益保留完整成本向量；不把节点下降但字节增加误记成负收益。

首版默认按确定性的阶段轮转、近期接受方向和有效尺度排序，收集成功率、耗时与收益，
暂不启用收益/秒评分。后续可以用调用次数和成本变化做确定性排序对照；
以实测耗时排序需要独立实验，不能悄悄破坏性能采集的行为等价契约。

新增报告 `scheduler` 信息并同步 schema 版本及文档。
报告由 schema 3 升级为 4；保留既有字段，增加策略、模型版本、阶段/方向/尺度
汇总和覆盖状态。基础计数独立于性能采集；耗时字段在未采集时为空。
现有候选 JSON 保持可重放，调度元数据可在日志中作为独立字段附加，不能成为接受条件。
耗时仅进入聚合报告或性能字段，不写入用于开关对照的有序决策内容。
性能采集开启时补充 scheduler 本身的时间与资源开销。

## 验收与实施顺序

实现按四个可独立审查的边界推进：

1. **抽取调度边界。** 引入反馈数据和 `LegacyScheduler`；固定预算下核对有序候选、
   拒绝原因、最终内容、计数、停止原因和最小性与当前第二批源码一致。
   单独覆盖编辑缓存的四类拒绝分支、内容命中、故障身份不匹配与预算异常；
   先不改变默认策略，也不混入新的搜索规则。
2. **稳定身份。** 实现可选节点搜索协议、旁路 ID 及克隆/删除/重排后的映射；
   验证身份不会改变序列化、摘要、成本和已有复合编辑行为。
3. **有状态调度。** 加入自适应分区、保留方向、阶段轮转、全局失效与最终覆盖，
   通过 CLI 显式启用。保留通用 pass 支持，节点专用状态通过显式可选接口接入。
4. **对照验收。** 扩展当前基准和报告，在同一第二批实现上比较两种调度器，记录
   最终覆盖的额外成本、结果质量及退化模型。根据数据再决定默认值和是否引入更复杂排序。

必须覆盖以下有实际行为断言的场景：

| 场景 | 核心断言 |
| --- | --- |
| 跨区域故障 | 故障依赖相隔区域中的两个触发节点；单一区域保留失败后仍能通过删除无关区域继续缩减 |
| 规模阈值 | 少于 K 节点就不 interesting；粗块失败后能细分，严格保留触发阈值 |
| 非单调规模 | 仅若干离散节点规模触发，例如 8、5、2；不以大块失败排除其他尺度或保留方向 |
| 旧失败变成功 | 固定触发节点 T 且条件为 `A 存在或 B 不存在`；删除 A 最初失败，删除 B 后必须能再尝试 A |
| 死节点触发 | 唯一触发节点不通向输出；无用节点清理仍经过故障判定并保留触发节点 |
| 位置失效 | 删除前缀、非连续补集和排序后，ID 对应实际选中节点；旧摘要的直接候选仍被拒绝 |
| 克隆与复合编辑 | 多次 `DeleteNodes` 按中间状态索引执行；存活身份准确，父模型完全不变 |
| 空图及输出 | 可删最后一个节点但保留合法输出；仅保留区域不隐式清理输出或资源 |
| 版本覆盖 | 前一版本全部失败后另一阶段接受，仍重访前一阶段；不能提前声明固定点 |
| 三态和故障身份 | 无法判定不入负面缓存、不证明最小性；其他故障不能被当作成功反馈 |
| 预算和结束 | 0/精确调用上限、缓存命中、准备后时间超限及最终强制复检维持现有语义 |
| 通用 pass 与公平性 | 自定义生成器不跨版本复用，连续接受不重置轮转额度，同名自定义节点 pass 不被替换，复用 engine 不泄漏调度状态 |
| 覆盖和缓存关闭 | 启发式耗尽仍进行最终扫描，`--no-cache` 不会被调度记账悄悄替代；覆盖接受后重新扫描新版本 |
| 采集开关 | 固定检查预算下，同一策略开关采集前后的有序决策及最终结果一致 |
