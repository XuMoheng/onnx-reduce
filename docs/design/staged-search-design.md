# 第四批：分阶段搜索和独立收尾

> 本文保留该批次的设计和当时的源码位置。当前模块职责与路径见[架构说明](../architecture.md)。

2026-11-03：新增实验性 `--scheduler staged`，默认继续使用 `legacy`。
现有 `stateful` 的候选顺序和接受后行为保留。实测见[第四批结果](../performance/performance-batch4-results.md)。

## 流程与职责

```text
校验、初检 → coarse → regions → fine → finalization → 实际输出文件加载、校验与强制复检
                ↑ 节点接受后最多两个 cleanup 尝试 ↑
```

`staged.py` 负责前三个搜索阶段；`finalizer.py` 独立负责固定点扫描。
两者都只提交候选，engine 仍通过同一个 `_try_candidate()` 处理编辑、成本、校验、
判定、故障身份与证据。接受门槛、字典序成本、第二批缓存与预算口径保持不变。
`search_types.py` 存放共享记录，`scheduler.py` 保留既有类型导入入口。

- `coarse`：内置 pass 中选择大小至少为 `max(2, 项目数//4)` 的分组。
  各资源集合和节点集合分别计算阈值；接受后在当前阶段重新生成当前模型候选，
  因而会恢复新规模的粗尺度，不延续一个已经不合适的旧尺度。
- `regions`：按模块、最大无分叉链、标准拓扑分区的顺序尝试删除和保留。
  启发式阶段只访问至少两个节点的区域；单项回退留给 fine 和完整收尾。
- `fine`：内置 pass 生成剩余小组及单项；通用自定义 pass 按原 `generate(model)` 执行。
- 每阶段连续 64 次无接受后让出，记录 `plateau`；任何准备拒绝、缓存命中和实际判定
  都计入尝试窗口，接受后清零。该内部常量尚未针对真实后端调优。
- 节点候选接受后，提供最多两个 `cleanup` 尝试，优先清理无用 input、initializer。
  清理接受也消耗这个额度，避免清理不断重置额度；输出清理仍属于原输出 pass。

阶段只能向后切换。后期接受不使启发式流程回到 coarse；新模型上遗漏的早期编辑由
独立收尾覆盖。快速运行不据此声称候选集合已穷尽。

`StagedPass.generate_stage(model, stage)` 是显式可选能力，内置三个 pass 已实现；
普通 pass 无需修改。节点区域能力仍通过 `NodeSearchPass` 接入，不能按 pass 名称识别。
模型没有节点身份能力时，在初次后端调用前报错；只有通用 pass 时无需节点协议。

## 区域来源和边界

`Region` 保存稳定节点 ID、来源、父模块路径、边界数量和缺失类型的边界数量。
所有执行索引与保留方向的补集都在当前模型上绑定，接受后丢弃旧区域快照。

首版支持明确的节点元信息约定：`NodeProto.metadata_props["onnx_reduce.module"]`
是非空 JSON 字符串数组，例如 `["encoder", "block0", "attention"]`。
每个路径前缀形成一个模块组，允许非连续节点。路径最多 64 层，每段最多 512 字符；
格式不满足约定时忽略该标注并回退。工具只读取已有标注，不写入模型或改节点名称。
没有经过验证的其他导出器字段暂不接入，节点名称前缀不推断为可靠模块。

结构分组采用主图中的最大无分叉链，在分叉、汇合处断开；控制流节点作为主图原子节点，
其子图捕获的外部值计入依赖。暂不做子图内部搜索、完整分支闭包或社区发现。
最后补充当前拓扑顺序上 `N//2` 逐次减半到 1 的标准分区。

同一来源内，边界类型完整、边界少的区域优先，再按规模和当前拓扑位置确定顺序。
边界质量不用于过滤。排序只读取现有类型，不调用 shape 推导。
图摘要按不可变模型实例缓存，编辑后失效；每次区域枚举仅保留当前版本的快照。

## 独立收尾的保证

`Finalizer` 对最终基准声明以下候选集合，范围版本为 1：

1. 全部配置 pass 的原始候选。
2. 启用节点能力时，各节点 pass 的标准尺度保留候选。
3. 启用节点能力时，当前模块、链、拓扑区域的删除和保留候选，包括单节点区域。

通用 pass 运行不自动增加节点候选。所有区域都针对最终模型重新生成，不将启发式阶段
访问记录当作覆盖。扫描中接受任何编辑，增加版本，使全部覆盖失效，并在 **finalization**
阶段重新开始扫描；不会再进入启发式搜索。

收尾维护最多 4096 项的同版本编辑去重表，独立于三种判定/准备缓存。重复的完全相同编辑
只需覆盖一次；表项淘汰只增加重复工作。生成器游标保证扫描结束，不依赖去重表容量。
`--no-cache` 仍禁用原三种缓存，调度层的同版本去重继续生效。

一轮完整、无接受、无 `inconclusive` 的当前版本扫描，加上最终产物复检成功，才报告
`minimality.status=pass_fixed_point`。它只表示声明集合内的固定点，不是全局最小。
最终扫描有不确定结果时，staged 使用 `stop_reason=coverage_inconclusive` 且最小性为
`unproven`。旧版本的不确定结果不会污染新版本证据。

## 运行目标和跨运行收尾

- `--scheduler staged --goal fast`：前三阶段完成、收益趋缓或预算耗尽后交付并复检。
  最小性始终 `unproven`；停止原因分别为 `search_exhausted`、`plateau`、`budget_exhausted`。
- `--scheduler staged --goal complete`：搜索后进入独立收尾；staged 不指定 goal 时也使用此目标。
  完整扫描仍受总预算限制，预算耗尽不会隐式追加额度。
- `--finalize-from RUN_DIR`：输入必须匹配该次成功运行的最终输出，跳过前三阶段，直接重新收尾。
  仅与 staged 的 complete 目标兼容。

跨运行入口读取源目录的 `task.json`、`target.json`、`replay.json`、`report.json`，
恢复原始结束方式及签名，核对输入摘要、源输出状态、判定命令、超时、三态规则、
目标模式、正则、校验模式和工作目录。源运行须已正常写出最终报告，不能仅提供 checkpoint。
命令仍由本次 `--test` 提供，配置必须与源运行一致；无法核验配置的自定义 runner 不支持此入口。

恢复后强制重新初检，但不会用新观察覆盖旧故障身份。因此另一故障即使也返回 interesting，
仍会因为身份不匹配而拒绝启动。预算可以重新设置；旧缓存、身份编号和扫描游标都不恢复。
普通加载 checkpoint 运行仍保持原来的“重新建立基线”语义。

预算仍是全运行共享的候选调用配额与软墙钟期限，搜索和收尾共同消耗。
初检与最终复检不占候选调用配额，但计入总调用统计；软时间从运行开始计时，包含初检。
不为收尾预留固定比例，搜索用尽总预算时仍为 unproven；需要单独投入收尾预算时使用独立入口。

## 交付和报告

ONNX 输出先物化到实际路径，再读取实际字节核对摘要，独立加载并按所选模式校验，
最后在该实际路径绕过判定缓存复检。读回校验失败属于工具错误；后端复检失败为
`unstable_check`，最小性为 unproven。通用适配器可通过可选的 `ArtifactValidationModel`
提供读回校验；未提供时仍进行现有的实际输出路径判定，报告标明未做读回校验。

报告升级为 schema 5，保留现有字段，增加 `artifact_recheck`。staged 的 scheduler 摘要增加：
阶段停止原因、分阶段接受成本变化、运行目标、范围版本、目标来源、收尾尝试、重启和去重次数。
`scheduler.sources` 分列 coarse、regions、fine、cleanup、coverage 的尝试、接受、
实际判定、缓存和可选耗时；`scheduler.jsonl` 在 staged 行增加 stage 和 region_source。
旧策略的候选与调度轨迹格式保持一致。

## 验收边界

覆盖旧策略等价、三态、总预算、快速目标不声明最小性、收尾接受后重扫、跨运行身份不漂移、
模块非连续成员、标注缺失/损坏、主图捕获、缺类型边界、去重表淘汰和实际产物损坏。
基准保留第三批紧预算、规模阈值、16/12/6 非单调退化，增加显式模块输入并比较四种运行。
真实后端故障、导出器专用模块解析和默认值切换仍需后续验证。
