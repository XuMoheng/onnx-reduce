## 性能问题

原始基线已经会按块删除节点，并非纯单节点遍历。放大效应来自“接受一次编辑就重头搜索”，以及每个候选都重复处理完整模型。第二批已降低资源候选数量和重复准备成本；重头搜索留到第三批调整。

| 原始基线行为 | 优化策略 | 收益来源 |
|---|---|---|
| 无用 input、initializer 和 output 逐个删除 | 整组尝试，失败后分组细分，最终回退到单项 | 减少检查和 checkpoint 次数 |
| 每次接受后从第一个 pass 重新开始 | 保存当前阶段、分区粒度和搜索位置 | 减少重复探索 |
| 多个候选反复对同一基准图推导 shape | 每个基准模型缓存一次推导摘要，包括失败结果 | 减少全图推导 |
| 成本计算导出模型，校验又重新导出 | 一次导出供校验、序列化和摘要计算复用 | 减少转换和内存分配 |
| 缓存查询发生在校验、落盘之后 | 增加编辑缓存，并将内容缓存查询移到落盘前 | 让命中真正省掉准备工作 |


在 `perf/reduction-strategy` 分支先分四批推进，先完成可测量的基础优化，再改搜索调度。每批独立验收，避免同时引入多个策略后无法判断收益来源。
前四批已完成合成场景验收；后续参考 `perf/free-try` 的 `666fc9b`，按第五、六批继续推进，
见[后续性能设计](../design/free-try-followup-design.md)。第五、六批已实现实验入口并完成合成矩阵验收，
见[本批结果](performance-batch56-results.md)；真实后端仍待验证。

**第一批：建立性能基线**

补充分阶段计时和基准测试，明确时间花在哪里。

采集开关、统计口径和基准命令见[性能基线](../../performance/performance-baseline.md)。

当前进度：采集和五类合成基准已实现；固定检查预算下的三轮开关对照通过，
详见[2026-11-02 实测](performance-batch1-results.md)。真实后端故障尚待验证。

- 计时覆盖：候选生成、克隆与编辑、shape 推导、序列化、校验、哈希、落盘、外部判定和 checkpoint。
- 记录候选规模、拒绝原因、缓存命中、累计写入量和峰值内存。
- 基准覆盖链图、分支图、多输出、大量 initializer、缺失 shape，以及真实后端故障。
- 同时比较固定检查预算、固定时间预算下的最终模型大小。

验收要求：能解释主要耗时组成，基线可重复运行；计时不改变搜索行为。

**第二批：降低候选数量和准备成本**

当前进度：批量清理与准备缓存已实现并完成合成基准验收，详见
[2026-11-03 实测](performance-batch2-results.md)。512 initializer 场景的实际判定从 515 次降为 4 次，
重复候选场景的 shape 推导从 381 次降为 1 次。真实后端另行评估；复合输出清理暂未启用。

拆成两个独立改动。

| 改动 | 实现内容 | 验收重点 |
| ---- | ---- | ---- |
| 批量清理 | input、initializer、output 先批量尝试，失败后细分，最终回退单项 | 覆盖全可删、部分不可删、组合删除、无法判定；始终保留至少一个输出 |
| 准备缓存 | 同基准模型共享 shape 推导摘要；复用一次导出的快照；增加编辑缓存，内容缓存前移到落盘前 | 相同输入与编辑的结果保持一致；缓存有版本、作用域和内存边界 |

批量清理还可以试验“删除输出＋关联死图＋无用资源”的复合候选，但失败后必须回退到独立编辑，避免漏掉可接受的缩减。

这一批优先复现已有的 512 个无用 initializer 场景，验证检查次数从逐项增长降为少量批次检查；真实后端另行评估。

**第三批：引入有状态搜索调度器**

当前进度：已实现独立调度器、稳定节点身份、自适应删除/保留分区、阶段轮转、版本失效和
最终覆盖，见[第三批设计](../design/stateful-search-design.md)。210 项测试与 60 组 legacy 等价对照通过，
完成 420 次主矩阵及 27 次轮转额度实验，详见[第三批实测](performance-batch3-results.md)。
`stateful` 显式启用，默认保留 `legacy`；同等预算下存在质量和运行成本退化，真实后端尚待验证。

这是主要的搜索架构调整。保留现有 pass 和编辑结构，由独立 scheduler 决定下一次尝试什么。

scheduler 在一次运行内维护：

- 当前阶段、分区粒度、搜索位置。
- 稳定节点 ID 与当前索引映射。
- 候选成功率、耗时和缩减收益。
- 模型版本，以及需要重新访问的区域。

节点搜索采用自适应分区，同时尝试“删除区域”和“仅保留区域”；成功后延续有效尺度，无进展再细分。接受候选后更新搜索状态，避免每次从第一个 pass 重头开始。

验收要求：

- 旧模型上的失败结果只能影响排序，不能直接排除新模型上的候选。
- 不使用失效的位置索引。
- 覆盖跨区域故障、规模阈值故障、死节点触发和非单调故障。
- 保留旧调度策略作为对照和回退入口。
- 在同等预算下比较结果质量，记录退化样本。

**第四批：分阶段搜索和独立收尾**

当前进度：已实现实验性 `staged`、模块/链/拓扑区域、fast/complete 目标、独立固定点扫描、
跨运行目标身份恢复和实际输出读回校验，见[第四批设计](../design/staged-search-design.md)。
277 项测试、60 组旧策略等价对照及 468 次基准通过，详见[第四批实测](performance-batch4-results.md)。
紧预算字节退化和尺度恢复样本有所改善，规模阈值与常规开销仍有退化；默认保持 `legacy`。
模块首版支持明确标注约定，导出器专用解析、真实后端故障和默认值切换尚待验证。

将完整流程组织为：

```
批量粗缩减 → 图区域缩减 → 细粒度搜索 → 固定点验证 → 最终产物复检
```

区域优先采用可靠模块信息，再考虑图结构分组，最后回退连续拓扑区间。边界数量和类型完整性用于排序，不能成为永久跳过区域的理由。

同时明确两种运行目标：

| 目标 | 停止方式 | 对外保证 |
| ---- | ---- | ---- |
| 快速缩减 | 时间预算耗尽或收益趋缓 | 得到有效且保留目标故障的较小模型 |
| 完整收尾 | 对最终模型完成声明范围内的扫描 | 达到该候选集合内的固定点 |

快速阶段不能声明最小性；收尾过程中如果接受了新编辑，需要重新完成相应验证范围。

**第五批：移植准备侧优化并补齐等价边界**

状态：已实现并完成行为等价与消融验收。实现私有 protobuf 快照、按需 IR、单 `DeleteNodes` 快速路径、有序图省排序，
以及有界校验/域缓存和 checkpoint 去重。复用现有 shape、编辑及内容缓存；
不重复计算 free-try 相对 main 的批量清理收益。

同一策略的候选顺序、内容、完整成本和固定点结论必须保持一致。快速路径补充边界元数据、
无序图、复杂类型、混合编辑和区域查询的差分验证；未证明等价的情况回退 IR。
最终实际产物的读回校验与后端复检绕过搜索缓存。详见[第五批设计](../design/free-try-followup-design.md#3-第五批降低准备和存储成本)。

**第六批：在 staged 内试验反馈续扫**

状态：已实现并完成合成场景验收，默认仍为 restart。以稳定节点 ID 和资源名维护阶段游标，coarse 保留尺度恢复，fine 接受后继续有效尺度，
cleanup 仍最多两次，固定点证明继续由独立 Finalizer 完成。保留旧策略及现有 staged 作为对照。

跨模型旧拒绝只能用于排序，不作为跳过依据；方向排序和历史延后分别消融。新增 gated、
one-stubborn-init，与阈值、16/12/6、跨区域、非单调和旧拒绝反转一起验收，
同时比较固定调用/时间预算的完整成本与收尾成本。gated-300 完整收敛约 19.5x，
方向/历史排序暂无稳定额外收益，阈值等旧差距仍保留。详见[第六批设计](../design/free-try-followup-design.md#4-第六批在-staged-内试验反馈续扫)
和[实测](performance-batch56-results.md)。

**第七批候选：真实后端、大模型存储和并行专项**

若近期主要处理大权重模型，在第五批测量 CopyFrom、payload 与权重占用后，可提前开展共享权重存储设计：
候选只写图和引用，权重保持不可变，内容身份覆盖实际权重，最终产物独立打包复检。

并行评估放在上述工作之后，根据测量决定是否实施。先比较并发 1、2、4 的墙钟时间、额外检查量和峰值资源占用，再选择默认值。

整个计划保留现有提交门槛：模型有效、成本严格下降、目标故障身份匹配，以及实际输出路径上的独立复检。
前两批的首个里程碑、第五批行为等价与第六批合成消融里程碑已完成。
